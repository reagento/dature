``cache`` parameter on ``dature.load()`` now accepts ``datetime.timedelta`` for TTL-based invalidation (in addition to ``bool``). Caching is also now supported in function mode (``load(..., schema=Cls)``) — the cache lives on the schema class as ``__dature_cache__``, shared with decorator mode and keyed by the participating sources. TTL is **bucket-aligned** (cron-style): the stored timestamp snaps down to ``monotonic % period == 0``, so every class loaded inside the same TTL window invalidates at the exact same instant, regardless of when each individual ``load(...)`` happened. ``LoadingConfig.cache`` accepts the same union, and ``DATURE_LOADING__CACHE`` can be set to a ``timedelta`` string (e.g. ``0:00:30``) for the same effect.
